# GPT-6.2 release evaluation, 17 November 2026

This evaluation covers orchestration 4.25.0 and code-review 1.23.0. Codex CLI 0.169.0 and Claude Code 2.1.326 ran fresh sessions against disposable repositories. Expectations and the source snapshot were written before each run. Native Codex discovery used an isolated marketplace and checked every installed candidate file against its source. Claude Code used the candidate plugin directories. The tests below distinguish normal plugin discovery from direct runner calls and prompt-based role calibration. The four cases exercise different properties. A detected defect can still fail the format or command-evidence contract.

Each repetition used a fresh session on the same fixture for that scenario. The strict prompt specifies the expected report structure and command evidence. The counts measure repeatability on these fixtures. The native host reviews in this report exercise other changes through the normal entrypoints.

## Premium authorization and host preflight

The first explicitly authorized Codex plan mentioned the user's Astra grant only in prose. Its JSON still assigned Sol to all roles. The Codex headless planning paragraph unconditionally required standard supervisors. The corrected paragraph distinguishes a restriction on planning-time children from a specific authorization for later execution. Independent inspection found only the untracked plan in each working tree, the original checkout still at its base, and only the original main ref in each bare remote. The native parent/child records confirmed separate contexts. Independent Git checks confirmed a clean tree and the original base and head. The PR discussion was supplied as a local export.

A second native handoff used an independently copied final package after the default effort was made explicit in the delivery instructions. ## Offline verification

All offline stages in `tests/run.sh` passed when run in groups. A combined run hit its time limit. The Codex runner was then tested in five disjoint groups covering all 81 named cases. Every group exited successfully (17, 16, 16, 16 and 16 cases). The stages before and after the runner passed using their original commands. The archive-fixture tests ran on Python 3.12, which provides the extraction filter they require. The fixed approval wording and the final default model and effort were checked again against the candidate.

Focused checks included 448 plan-linter assertions, the old/new model and premium-role compatibility cases, 17 telemetry cases and the PR evidence scorer’s self-test. The telemetry cases cover the exact 272,000-token boundary, mixed short and long requests in one fixed-model trace, and unknown cache-write retention. Offline tests establish these contracts and the runner’s state transitions. The model judgments and actual host discovery are covered by the live cases above.

## Reproducing the live checks

Run these commands from the repository root with the appropriate host signed in. Each review series needs a fresh output directory. The strict runner writes `cells.tsv` plus prompts, answers and tool traces for each cell. The supervisor and dependency-audit drivers print their scored cases. Substitute `gpt-6.2-astra` for the supervisor only when its premium role is authorized.

```sh
EVAL_PROVIDER=codex EVAL_MODEL=gpt-6.2-sol EVAL_EFFORT=high EVAL_REPEAT=5 EVAL_RESULTS_DIR="$(mktemp -d)" bash tests/eval/critical-review.sh
EVAL_PROVIDER=codex EVAL_MODEL=gpt-6.2-sol EVAL_EFFORT=high bash tests/eval/supervisor.sh
bash tests/eval/seam-audit-fixtures.sh --provider codex --model gpt-6.2-sol --effort medium
python3 tests/eval/premium-plan-live.py --provider codex --case asked --out "$(mktemp -d)/asked"
python3 tests/eval/premium-plan-live.py --provider codex --case unasked --out "$(mktemp -d)/unasked"
```
