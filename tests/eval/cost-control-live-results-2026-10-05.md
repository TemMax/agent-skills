# Cost controls: реальные Claude Code и Codex, 2026-10-05

Первые три выбранных сценария проверены на настоящих моделях и CLI: восстановление
готового коммита после сбоя окружения, потерянная валидация при зелёных тестах,
объяснение PR и продолжение ограниченной задачи в четырёхходовом диалоге.
Кандидаты — orchestration 4.8.0 / code-review 1.15.0 из рабочего дерева;
база — 4.7.2 / 1.14.1 из HEAD. Полная acceptance matrix ещё не завершена,
пакет целиком не объявлен release-ready и рабочая установка не обновлена.

## Поведение и качество

| Проверка | Claude Code | Codex |
| --- | --- | --- |
| Первый исполнитель оставил чистый коммит, затем проверка окружения упала | Да | Да |
| После исправления окружения повторно запущены проверки и независимое ревью | Да | Да |
| Исполнитель не повторялся; закреплённый HEAD сохранился | 1 executor + 1 reviewer на всю цепочку | 1 executor + 1 reviewer на всю цепочку |
| Продолжение после двух вызовов не сбросило лимит | Да, новых вызовов 0 | Да, новых вызовов 0 |
| Из 39 зелёных тестов ни один не проверяет отрицательные значения | Настоящий reviewer отклонил удалённый guard | Настоящий reviewer отклонил удалённый guard |
| Ложный отчёт «validation remains intact» замечен | Да | Да |
| Нормальная загрузка тестового скилла | Host injection совпадает с телом снимка | Реальный прочитанный cache-файл совпадает по SHA-256 со снимком |
| Объяснение документационного PR без изменений/детей | Да | Да |
| На продолжении изменена только строка CI 10 → 15 | Да после двух выявленных неудач и исправления | Да |
| Повторное чтение скилла / новый вопрос согласования / объявление профиля | 0 / 0 / 0 в финальном прогоне | 0 / 0 / 0 в финальном прогоне |

Это точечные проверки, не доказательство одинакового качества на любых задачах.
Semantic A/B сравнивает старый и новый supervisor prompt поверх одинаковых
независимых фактов; это не сравнение стоимости старого полного pipeline.

## Измеренные токены

Вход включает кэши. Для Claude обычный вход, создание кэша и чтение кэша
складываются; для Codex cached input уже входит в input. Output показан отдельно.
Один финальный прогон на вариант; статистической оценки экономии нет.

| Сценарий / область | Старый вход | Старый output | Новый вход | Новый output | Изменение суммы |
| --- | ---: | ---: | ---: | ---: | ---: |
| Codex, восстановление, весь native pipeline | 221 046 | 2 171 | 114 294 | 1 183 | −48,3% |
| Claude, восстановление, все дочерние роли | 429 263 | 6 739 | 300 509 | 4 168 | −30,1% |
| Claude, отдельно старый Workflow coordinator | 164 821 | 1 578 | отсутствует в native CLI driver | — | другая транспортная схема |
| Claude, четыре хода PR/skill/CI | 347 238 | 876 | 223 750 | 622 | −35,5%; старый вариант изменил лишний файл |
| Codex, четыре хода PR/skill/CI | 144 828 | 736 | 260 649 | 960 | **+79,7%** |
| Claude, semantic reviewer | 287 118 | 1 729 | 215 453 | 1 565 | только узкий prompt probe |
| Codex, semantic reviewer | 54 503 | 1 030 | 36 070 | 727 | только узкий prompt probe |

Codex recovery: обычный вход 36 726 → 27 254, cache read 184 320 → 87 040;
cache creation отдельно не сообщён. Claude recovery по дочерним ролям:
обычный вход 202 → 134, cache creation 55 722 → 25 225, cache read
373 339 → 275 150. С учётом отдельного старого Workflow coordinator захваченная
сумма Claude составляет 602 401 → 304 677; основное сравнение оставлено по
дочерним ролям, чтобы не скрывать разницу транспорта.

Старый recovery специально выполняет полный перезапуск: Codex 2 executor +
1 reviewer, Claude 2 executor + 2 verifier + 1 reviewer. Старый Workflow тоже
поддерживает cached-agent resume; его оптимальный resume здесь не измерен.
Процент относится к этой стратегии и фикстуре, а не ко всем старым сессиям.

В четырёхходовом Codex прогоне новая модель сделала больше отдельных чтений:
например, первый ход выполнил пять команд вместо двух. Один прогон не отделяет
случайную вариативность от влияния инструкций. Экономия на коротком диалоге
Codex **не подтверждена**; следующий этап должен уменьшить загружаемую часть
entrypoint и проверить тот же сценарий, сохраняя ограничения по качеству.
API usage и reported cost не равны расходу лимита подписки.

## Дополнительные защитные проверки

На полученных живых кандидатах настоящий native runner, без новых вызовов
модели, отверг отсутствующий required link, исчезнувший lock-файл вместо
стабильного writable directory, изменение бюджета и изменение HEAD.
С существующим каталогом он реально повторил команды. Изменённый `must_run`
вернул exit 9; старые зелёные факты и вердикт его не перекрыли. Возврат зелёной
команды на исчерпанном лимите остановился, не перенося прошлый positive verdict.

Codex отклонил противоречие «all executor commits must be signed» до моделей;
после тестовой авторизованной правки на защиту persistent signing configuration
проверки выполнены заново. Сам signing config не изменён. Независимое
положительное ревью исправленного signing contract при свободном бюджете ещё
не проверено; положительная acceptance всего signing-сценария не заявляется.

Guard probe в конце намеренно продвинул только одноразовый candidate HEAD,
сохранив исходный коммит в `evidence/original-candidate`. Первоначальные отчёты
фиксируют исходный HEAD. Эти изменённые фикстуры больше нельзя выдавать за
неизменённые текущие репозитории.

## Найденные проблемы и сохранённые неудачи

- Первый Codex recovery driver передал неподдерживаемый `--default-branch`:
  запуск остановился до моделей. Флаг оставлен только Claude.
- Первый старый Claude Workflow отклонил scriptPath вне разрешённого каталога.
  Этот оплаченный coordinator transcript сохранён: 55 186 токенов. Следующий
  запуск использовал actual Workflow с файлом внутри fixture и узким `--add-dir`.
- Codex navigation new-1 прочитал установленный 4.7.2: это **не** проверка
  кандидата. New-2 не обнаружил скилл. Исправлены temporary installation и
  literal CLI override keys; discovery проверяется до моделей.
- Claude navigation new-1 и new-2 изменили README сверх заданной строки CI.
  Модель предложила новую правку, затем приняла «продолжай в том же объёме» за
  разрешение. Инструкции теперь отделяют ограниченную одиночную правку от
  полного планирования, требуют закончить в названных файлах и сообщать
  несоответствия без вопроса о дополнительной работе. New-3 прошёл.
- Старый Claude navigation тоже изменил лишний README и объявил профиль;
  старый Codex navigation прошёл. Это сохранённые исходные наблюдения.
- Первый Codex guard запуск был заблокирован nested macOS sandbox, новых
  моделей 0. Следующий native запуск выполнен вне внешнего sandbox.
- Guard assessor первоначально искал Codex facts в Claude JSON paths. Факты
  уже находились в native state, включая exit 9. Исправлен parser, предыдущий
  failed assessment сохранён; `assessment-v2.json` пересчитан без runner/model
  rerun. Сам runner не менялся из-за этой ошибки стенда.
- Найден повторный подсчёт накопительных Codex usage после `exec resume`.
  Анализатор теперь вычитает предыдущий счётчик, когда накопление подтверждено
  `total_token_usage` собственного rollout. Все числа выше пересчитаны.
