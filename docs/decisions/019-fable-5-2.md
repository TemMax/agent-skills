# 019 — Fable 5.2 runs only as the user's session: orchestrator and reviewer

Date: 2026-11-10
Status: accepted

## Context

Claude Fable 5.2 (`claude-fable-5-2`) shipped on 2026-11-09 with the Claude
Fable 5.2 & Mythos 5.2 system card (264 pp.). Before this change a session on
it matched no profile row, so super-plan, ship, multi-model and
critical-review ran it on the generic profiles.

- The user decided on 2026-11-10 how the model is used: Fable 5.2 is only the
  session the user talks to — the orchestrator (super-plan, ship,
  multi-model) and the reviewer (critical-review) — and never an executor.
- The alias had already moved under the skill: `claude -p --model fable`
  billed `claude-fable-5-2`, and an Agent-tool spawn with `model: fable`
  reported `resolvedModel` `claude-fable-5-2` (Claude Code 2.1.322). The alias
  table still mapped `fable` to Fable 5.1, so a spawn written for Fable 5.1
  through the alias would have started Fable 5.2 as a child.
- The plan linter and the wave runner accept only the Claude IDs they list;
  `claude-fable-5-2` is not among them.

## Decision

1. **Fable 5.2 is a seat, never a child.** It runs as the orchestrator seat
   and the reviewer seat. It is never an executor, research agent, ladder rung
   or supervisor, and it is not a plan model: the linter rejects
   `claude-fable-5-2` as an executor, supervisor or ladder rung, and the
   runner does not know the ID. Every spawn from its seat names a routed
   model, since an unnamed one inherits the seat; the Opus verifier and the
   independent check of a direct fix run on Opus 5.5. The skills say so
   where a route is chosen.
2. **Step 0 selects its own profiles.** `claude-fable-5-2` maps to
   `orchestrator-fable-5-2.md` in super-plan, ship and multi-model and to
   `reviewer-fable-5-2.md` in critical-review. The profiles carry the card's
   findings that matter in those two seats, with page references, and
   nothing about executor work.
3. **Nothing is spawned through `fable`.** The alias table maps `fable` to
   Fable 5.2 with the probe date; Fable 5.1 has no alias and is spawned only
   through Workflow `agent()` with its full ID, like Opus 5 and Opus 4.8.
4. **Fable 5.1 keeps its routes.** It stays a premium executor, rung and
   supervisor under `approvals.premium`; this decision changes none of them.

## Consequences

- A Fable 5.2 session plans and reviews under its own profile instead of the
  generic one.
- Wave costs are unchanged: no plan can route work to Fable 5.2, so its price
  ($8 / $40 per million input / output tokens) is paid only for the user's own
  session. Its research fan-out goes through the Research Routing table like
  any seat's.
- A plan written for a Fable 5.2 seat names the same executors and
  supervisors as one written for any other Claude seat.
- When the next Fable ships, `fable` moves again; the alias row is dated and
  the model line in spawned agents' reports catches the move.

## Evidence and limits

The card excerpts, probes and live runs are in
[`tests/eval/fable-5-2-results-2026-11-10.md`](../../tests/eval/fable-5-2-results-2026-11-10.md).

- The profiles' guidance is grounded in the card. The card measures the model,
  not these skills; the live runs show that the profiles load and that the
  skills' outcomes hold on the seat, not that the profile text makes the model
  better than the generic profile.
- Codex is unchanged apart from the version numbers: its entrypoints and
  workflow copies were not edited, and no Codex run was made.

## Rejected alternatives

- **Fable 5.2 as an executor, rung or supervisor.** Ruled out by the user's
  decision.
- **Adding `claude-fable-5-2` to the linter with a seat-only marker.** The
  linter's lists are shared with Codex plans and gate what can run; the ID has
  no plan role, so it stays out of them, and an unknown ID is already an
  error.
- **Replacing Fable 5.1's premium routes with Fable 5.2.** Fable 5.2 is never
  a child, so those routes keep Fable 5.1.
