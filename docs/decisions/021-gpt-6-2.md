# 021 — GPT-6.2 Astra and Sol

17 November 2026. Applies to orchestration 4.25.0 and code-review 1.23.0 in Claude Code and Codex.

## Model selection

| Role in a new Codex plan | Model and effort | Basis |
|---|---|---|
| Narrow edit with complete instructions | GPT-6 Luna at medium, optional GPT-6.2 Sol rung | Existing mechanical lane and task-specific escalation |
| Ordinary or difficult implementation | GPT-6.2 Sol at medium or high, respectively | A real executor produced a passing commit and a separate supervisor accepted it |
| Research or plan dependency audit | GPT-6.2 Sol at medium | Independent audit dispatch in real planning and ten scored dependency fixtures |
| Standard wave supervisor | GPT-6.2 Sol at high in a fresh session | Four supervisor scenarios, nine assertions, plus a native end-to-end wave |
| Premium executor, last rung or supervisor | GPT-6.2 Astra at the approved effort | Positive wave, adverse review cases and recovery on the same commit |
| Advisory drift hook for either 6.2 seat | GPT-6.1 Sol at high | Existing separate judge, previously qualified on held-out transcripts and exercised through both new seats |
| Final integrated review | GPT-6.2 Sol at high in a fresh session | 10/10 reviews of a clean change, 10/10 reviews of a planted defect and 4/4 runs across two local PR authorization scenarios. A reviewer dispatched by the delivery entrypoint also reproduced a regression missed by 39 passing tests. [Evaluation](../../tests/eval/gpt-6-2-results-2026-11-17.md) |

The exact host ID selects the active profile for planning, execution coordination, delivery and review. Unknown IDs select the generic profile. Unknown effort stays unknown. A user already working in Astra can plan and review on that seat. Creating an Astra child requires authorization for the exact generation and role. The coordinator records it in the plan. An Astra executor or rung also needs a concrete task reason and a fresh supervisor on the same exact ID. An approval issued for the previous Astra cannot authorize the new model. Previously approved plans retain their recorded models and efforts.

The source of the decision is OpenAI’s joint 119-page card and the two API model pages. The card reports better results on several adversarial workplace evaluations alongside more failures to disclose obstacles and more instruction-following flags on internal task replays. Executors must account for unavailable checks. Supervisors rerun the contract and inspect the committed result. Reports keep model identity and internal handoff details out of the task evidence. ## Cost and validation

The telemetry tool selects the published Standard price tier for each API request before summing a multi-request session. The higher tier begins above 272,000 input tokens. Token counts remain available for cache writes whose retention price cannot be determined. The local wave estimates are reference-price calculations. Host subscriptions and other service tiers can charge differently.
