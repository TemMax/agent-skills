журнала взят максимум каждого счётчика; затем ответы суммированы. Сумма всех

их нельзя автоматически приравнивать к единицам подписного лимита.

## Что изменено сейчас

- Профиль выбирается молча. Сообщения описывают задачу, изменения, находки,
  выполненные проверки и препятствия. Названия моделей и данные калибровки
  остаются в служебных артефактах, необходимых согласованиях выбора маршрута
  и ответах на прямые вопросы о моделях.
- Принятый результат не отправляется в новый цикл только из-за `remarks`.
  Необязательные улучшения откладываются либо отклоняются с причиной;
  необходимые исправления объединяются в одну задачу.
- Агент получает контракт, базу, пути и нужные решения. Полная дискуссия и
  полные build-логи не копируются в prompt. Это инструкция по подготовке
  контекста; она сама по себе не уменьшает набор инструментов, который
  автоматически добавляет хост.
- Супервизор использует независимые verifier facts для той же ветки и pipeline.
  Повторный запуск требует конкретной причины. Дополнительные пробы и мутации
  отвечают на нерешённый вопрос контракта, а не расширяют проверку без предела.
- Исполнитель и effort выбираются по сложности задачи в пределах существующих
  маршрутов. Правила независимости и допустимых супервизоров сохраняются.
- Исправлен [анализатор usage](../../tests/eval/telemetry/telemetry.mjs):
  удаление повторов по message ID и учёт кэшированного входа в размере контекста.
  Раньше он завышал количество запросов и токены, а средний вход показывал без
  кэшированной части. Добавлен тест с несколькими записями одного ответа.

## Следующий этап оптимизации: исходные предложения

Наибольший резерв — уменьшить число полных запусков проверки, а не отключить
контроль качества или запретить дорогую модель.

1. **Проверка масштаба задачи до делегирования.** Небольшая самостоятельная
   правка, для которой нет смысла создавать волну, остаётся обычной работой
   одного агента с локальной проверкой. Для активных планов нужен отдельный
   режим механической проверки, а не исключение по числу строк. Сейчас Codex
   требует модельного супервизора даже для механических задач; Claude-проза
   допускает shortcut, но штатный runner всё равно вызывает судью.
2. **Механическая проверка без агента.** Codex уже выполняет часть проверок
   детерминированно. У Claude verifier пока тоже агент. Перенос исполнения
   команд, проверки путей и сбора выходов в код уберёт дополнительный модельный
   цикл там, где решение полностью определяется контрактом.
3. **Повторная проверка только изменившегося результата.** Сохранять результаты
   с SHA артефакта, контрактом, порядком команд и отпечатком окружения. После
   доводки инвалидировать затронутые проверки; полный CI запускать на итоговом
   интегрированном состоянии. Результаты другой ветки или окружения не переиспользовать.
4. **Компактные запросы и логи.** Измерять стартовый вход каждого агента,
   выводить только нужные фрагменты, а полный вывод сохранять в файл. Для
   крупных задач делить работу по границам модулей и сохранять краткий handoff,
   прежде чем контекст разрастётся до сотен тысяч токенов.
5. **Бюджет повторов на задачу.** Записывать usage по ролям и попыткам; если
   один и тот же дефект или неопределённость переживает ограниченное число
   циклов, останавливать автоматические повторы и менять контракт или подход.
   Число циклов и денежные пороги должны быть настройками, а не догадкой модели.

На момент первого прохода пункты этого этапа требовали изменений runner,
формата состояния и отдельных проверок совместимости. Экономия от новых
инструкций ещё не измерена в живом A/B-прогоне; офлайн-тесты подтверждают
контракты и подсчёт usage, а не процент сокращения реального расхода.

Проверены структура, общий контракт скиллов, все `tests/contracts/*.test.sh`
и 28 тестов телеметрии. Полный `tests/run.sh` остановлен на длительном этапе
Codex wave-state; успешный полный прогон не заявляется. Платные модельные
прогоны не запускались. Изменения находятся в рабочем репозитории, доставка
в установленные копии плагинов в эту задачу не входила.

## Реализовано после одобрения следующего этапа

- Native Claude runner запускает независимую проверку в коде, без verifier-модели.
  Стандартная успешная задача требует двух вызовов модели: исполнитель и судья.
- Оба native runner поддерживают явный `supervision: "mechanical"`: один вызов
  исполнителя для полностью проверяемого командами успешного контракта. По
  умолчанию модельная проверка сохраняется. Семантические запреты и вопросы
  отчёта несовместимы с этим режимом; красные факты блокируют принятие.
- Повторно используется только целиком зелёный pipeline с тем же SHA,
  контрактом, порядком команд и отпечатком окружения. Каждый `must_run` должен
  явно объявить `cache: "artifact"`. Изменение коммита инвалидирует все команды;
  автоматическое определение зависимостей отдельных проверок не реализовано.
- Claude CLI получает отдельную сессию и ограниченный набор инструментов.
  Полный вывод сохраняется в файлах, модель получает ограниченные фрагменты.
  Судья проверяет закреплённый коммит в отдельном checkout; его изменение
  отклоняет результат. Таймаут команд завершает дочерние процессы сборки.
- `limits.max_attempts` и `limits.max_model_calls` ограничивают повторы на
  задачу, включая ошибки запуска и формата. Достижение лимита сохраняет
  артефакты и останавливает новые вызовы. Это лимиты вызовов, а не токенов.

Подробности и условия безопасного применения:
[execution-cost-controls.md](../../plugins/orchestration/skills/multi-model/references/execution-cost-controls.md).
Снижение числа вызовов подтверждено офлайн-фикстурами с подставным CLI.
Экономия реальных лимитов подписки ещё не измерена; платные A/B-прогоны не
запускались. Изменения подготовлены в исходном репозитории.

Проверка второго этапа: выполнен полный офлайн-набор. Единственный упавший
набор проверял доступность вложенного sandbox при подставном CLI; настройка
тестового окружения исправлена, его повторный прогон прошёл 40/40. Остальные
наборы полного прогона прошли. После последних исправлений отдельно прошли
8 тестов Claude runner, 7 тестов механической проверки, 110 структурных
проверок и 285 контрактов скиллов. Проверка итоговых изменений выявила два
дефекта — очистку после таймаута и смену HEAD судьи; оба исправлены и покрыты
регрессионными проверками.

## Дополнение для GPT/Codex

Оптимизации runner распространяются на Codex: его verifier уже выполнялся
в коде, теперь доступны явный механический вердикт, переиспользование pipeline
и лимиты вызовов. Отдельно уточнены инструкции скиллов:

- Координатор выполняет короткие чтения напрямую; отдельный исследователь
  нужен для содержательной самостоятельной задачи.
- Ревью читает функции и вызовы, расширяя чтение до файла по необходимости.
  Проверяющий изучает утверждения тестов и независимые результаты; повтор
  зелёной проверки требует изменения артефакта или конкретного сомнения.
- `ship` переиспользует полный офлайн-прогон финальной волны только при том же
  интегрированном HEAD, командах и окружении, с сохранёнными выходами. Финальное
  независимое ревью PR остаётся; ему передаются требования и пути к артефактам.
- Досье GPT читаются для вопросов выбора модели и калибровки. Обычная работа
  применяет профиль и правила маршрутизации, сохраняя их ограничения.
- Инструкции Codex больше не требуют модельного судью для принятого явно
  механического задания вопреки результату native runner.

Общие правила ревью и передачи артефактов синхронизированы между версиями
скиллов. Структура (110), контракты скиллов (285) и все отдельные контрактные
наборы прошли. Это изменения инструкций; платные проверки поведения не
запускались. Стандартный skill-creator validator недоступен в системном Python
из-за отсутствия PyYAML; применены репозиторные проверки frontmatter и парности
Codex/Claude. Установленные пакеты пока не обновлены.
