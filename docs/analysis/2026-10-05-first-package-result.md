# Первый пакет оптимизации: результат

Подготовлены исходники orchestration 4.8.0 и code-review 1.15.0 для Claude и
Codex. Это завершение трёх изменений из
[плана](2026-10-05-optimization-roadmap.md), с ограничениями ниже.

## Реализовано

- Нативные runner принимают `--resume-from <summary.json>` и новый `--out`.
  Они проверяют и рецензируют готовый кандидат без исполнителя. Отрицательный
  результат останавливает восстановление, не запускает новую реализацию.
- Кандидат закреплён за чистой рабочей копией, коммитом и базой; сохраняются
  задача, роли, разрешения и лимиты. Все прежние child launches учитываются.
  Старый положительный вердикт не переносится. Исправленный контракт проверяется
  заново. Режим восстановления использует максимум 24 вызова при отсутствии
  явного ограничения. Один receipt нельзя продолжить дважды; цепочка использует
  последний summary. Состояние и доказательства прошлых запусков сохраняются.
- Очистка Codex не удаляет кандидат незавершённого восстановления. После
  завершения восстановление можно намеренно очистить штатным reset.
- В восьми entrypoint закреплены один владелец фазы, использование загруженных
  инструкций, сохранение согласованных решений и разрешений в пределах scope,
  целевые чтения и короткие выдержки ошибок. Объяснение PR исключено из discovery
  critical-review. Ранее подготовленное скрытие служебных объявлений сохранено.
- Обязательные links не пропускаются молча; необязательные задаются через
  `optional_links`. Явные writable roots должны быть существующими стабильными
  каталогами. Известные противоречия unsigned executor / signing / squash
  выявляются до исполнения. CLI availability проверяется без вызова модели;
  это не проверка удалённой авторизации. Preflight собирает найденные блокеры.
- Содержательное независимое ревью сохраняется. Проверки Codex-судьи также
  закреплены за коммитом и отвергают изменение checkout, HEAD или task branch.

Архив: `/tmp/agent-skills-4.8.0-1.15.0.tar.gz`.

## Что это доказывает

В сценарии восстановления сохраняется один вызов исполнителя на всю цепочку;
добавляется только требуемое ревью. Увеличение лимита, изменение ролей,
грязная копия и изменённый HEAD отвергаются. Изменённый `must_run` реально
выполняется; его красный результат не перекрывает прошлый зелёный результат.
Отрицательный вердикт независимого судьи не вызывает исполнителя повторно.

Заглушка судьи проверяет прохождение отрицательного вердикта через runner,
а не способность живой модели заметить утрату инварианта. Уменьшение повторных
чтений и согласований также требует проверки поведения модели, а не только
текста скилла. [Сценарии живой оценки](../../tests/eval/first-package-regressions.md)
подготовлены; на этом первоначальном этапе платные прогоны не выполнялись.

## Последующая живая проверка

Три выбранных сценария теперь проверены в настоящих Claude Code и Codex,
со старой версией, снимками текущих файлов и сохранёнными неудачами. Детали,
токены и оставшиеся условия — в [отчёте живого стенда](../../tests/eval/cost-control-live-results-2026-10-05.md).
Восстановление сохранило один вызов исполнителя; обе модели обнаружили
потерянную валидацию при 39 зелёных тестах. После выявленного нарушения scope
исправлена одиночная правка в multi-model; финальное продолжение проходит на
обоих хостах без повторного чтения, согласования и объявления профиля.

На фикстуре восстановления сумма токенов снизилась на 48,3% у Codex и 30,1%
у дочерних Claude-ролей. В коротком Codex-диалоге она выросла на 79,7% в одном
сравнении. Общее снижение расхода по пакету и неизменность качества на любых
задачах не доказаны. Исправлен двойной подсчёт накопительных Codex usage;
сохранённые данные можно пересчитать без вызова моделей.

После этих исправлений полный `bash tests/run.sh` прошёл с exit 0. Live-прогоны
выполнялись отдельно; оставшиеся live quality conditions этим не закрыты.

## Доставка

Версии, changelog и документация подготовлены. Ранее собранный архив относится
к первоначальным файлам и не включает последующие исправления стенда/скилла.
Установленные marketplaces обоих хостов сейчас смотрят на GitHub; автоматически
они не получают незапубликованные изменения этого checkout. Рабочая установка
не обновлена: полная [обязательная live matrix](../../tests/eval/first-package-regressions.md)
ещё не завершена. Для проверок использованы отдельные локальные копии, temporary
Codex IDs удалены штатным CLI, источник temmax не менялся. После завершения
обязательных проверок пакет надо пересобрать, обновить установку и проверить
реально загруженные файлы в новой сессии.

Этот пакет не создаёт универсальный менеджер host services или ресурсов,
полноценный merge workflow, сквозной токеновый бюджет, автоматическое сжатие
сессий или доказательство полной идентичности toolchain. Восстановление пока
требует кандидатов всех задач выбранной волны и receipt новой версии; старые
summary не принимаются автоматически. Восстановление оборванного процесса без
финального summary не заявляется как поддерживаемый режим.
